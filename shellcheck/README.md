# vsc: a drop-in replacement for ShellCheck, in Vu

`vsc` is ShellCheck 0.11.0 rewritten in Vu: the same command line, the same output in every
format (byte for byte, fixes included), the same `.shellcheckrc` lookup and directives, the same
exit codes, the same behavior on unreadable files, broken pipes, full disks and non-UTF-8 locales,
and all of ShellCheck's checks: the 511 codes in its source (SC1000-SC1146 parse
messages, SC2000-SC2335, SC3001-SC3067 bashisms) and its 11 optional checks. It uses 25 times less
CPU (below). It is a port of ShellCheck's own design, about 16,500 lines of Vu in this directory (plus
a generated Unicode table):

| file | what | ShellCheck source |
|---|---|---|
| `parse.vu` | the parser, with every SC1xxx parse warning and error, `.shellcheckrc` parsing, following sourced files | `Parser.hs` |
| `ast.vu`, `astlib.vu` | the syntax tree (flat arrays) and its helpers | `AST.hs`, `ASTLib.hs` |
| `check.vu` | variable flow, every check, fixes, `# shellcheck disable=` filtering, post-dominators | `AnalyzerLib.hs`, `Analytics.hs`, `Checks/*.hs` |
| `cfg.vu`, `dfa.vu` | control flow graph and the data flow analysis over it | `CFG.hs`, `CFGAnalysis.hs` |
| `data.vu` | variable lists | `Data.hs` |
| `fmt.vu` | the output formats, applying fixes, the diff | `Formatter/*.hs`, `Fixer.hs`, the Diff package |
| `vsc.vu` | command line (GetOpt), rc file lookup, reading files, paths, `--jobs N` workers | `shellcheck.hs`, the directory and filepath packages |
| `ucd.vu` | GHC's `Data.Char` (Unicode 15.1 categories and case mappings), generated by `test/gen_ucd.py` | `GHC.Unicode` |
| `sys_glue.c` | the system as ShellCheck's binary sees it: GHC's text handles (locale encoding, buffering, write errors), file name decoding, reading files (errno messages as musl prints them), realpath, isatty | GHC's IO library, musl |
| `test/` | corpus collection, reference runs, comparisons, attack generator, command line cases, benchmark | |

```
./vu build --release shellcheck/vsc.vu -o vsc
./vsc [OPTIONS...] FILES...       # exactly shellcheck's options; see ./vsc --help
```

## Install

Releases are tagged `vsc-vX.Y.Z` (vsc's own versions; every one checks as ShellCheck 0.11.0 does).
Each channel installs `vsc` and `shellcheck` (the same program), so scripts and editors that call
`shellcheck` keep working. Linux x86-64 and ARM64 (static binaries: any distribution, glibc or musl)
and macOS 12 or later (Apple silicon, Intel).

```sh
# into ~/.local/bin (-b DIR elsewhere; a version as the last argument, else the latest release)
curl -fsSL https://raw.githubusercontent.com/vu0tran/vu/main/packaging/tools/install.sh | sh -s -- vsc

# npm: in place of the `shellcheck` npm package, one line in package.json
#   "shellcheck": "npm:@vu0tran/vsc@^0.1.0"
npm install --save-dev @vu0tran/vsc
```

The release archives are named as ShellCheck's, with `vsc` for `shellcheck`:
`vsc-v0.1.0.linux.x86_64.tar.xz` (`linux.aarch64`, `darwin.x86_64`, `darwin.aarch64`), holding
`vsc-v0.1.0/vsc` and `vsc-v0.1.0/shellcheck`, so a Dockerfile line that unpacks ShellCheck's archive
changes only its URL and names:

```sh
curl -fsSL https://github.com/vu0tran/vu/releases/download/vsc-v0.1.0/vsc-v0.1.0.linux.x86_64.tar.xz | tar -xJf -
cp vsc-v0.1.0/vsc /usr/local/bin/shellcheck
```

**GitHub Actions**, in place of `ludeeus/action-shellcheck` with the same inputs (`scandir`,
`severity`, `format`, `ignore_paths`, `ignore_names`, `additional_files`, `check_together`), the same
file discovery and outputs; `version` names a vsc release:

```yaml
- uses: vu0tran/vu/shellcheck/action@vsc-v0.1.0     # was: ludeeus/action-shellcheck@master
  with:
    scandir: ./scripts
    severity: warning
```

**pre-commit**: in place of `shellcheck-py/shellcheck-py` or `koalaman/shellcheck-precommit` (the
hook runs the vsc on PATH, so install it first):

```yaml
- repo: https://github.com/vu0tran/vu
  rev: vsc-v0.1.0
  hooks:
    - id: shellcheck
```

or, with nothing installed beforehand, pre-commit's own node environment fetches a pinned vsc from npm:

```yaml
- repo: local
  hooks:
    - id: shellcheck
      name: shellcheck (vsc)
      language: node
      additional_dependencies: ['@vu0tran/vsc@0.1.0']
      entry: shellcheck
      types: [shell]
```

## Drop-in status

**Nothing known differs.** On every file ShellCheck finishes, vsc's stdout, stderr and exit status
are byte for byte ShellCheck's, in every format and with every option, as far as all the tests
below can tell (7,601 real scripts, 385 command line cases, 17,700 generated and mutated scripts);
the only differences left are where ShellCheck can't finish (it runs out of memory or hangs, below).
The reference is the official ShellCheck 0.11.0 release binary (static, GHC 9.8.2 with musl).

**Command line.** Every option of `shellcheck --help`, parsed as GHC's GetOpt parses them
(bundled short options, `-fgcc`, `--format=gcc`, unique prefixes of long options, `--`, the same
messages for unknown, ambiguous and missing arguments, exit 3), and `SHELLCHECK_OPTS`:

| option | status |
|---|---|
| `-a`, `--check-sourced` | supported |
| `-C[WHEN]`, `--color[=WHEN]` | supported (auto: stdout is a terminal and `TERM` isn't empty or `dumb`) |
| `-i`, `--include` / `-e`, `--exclude` | supported (`SC` prefixes, repeated options, `Invalid number`; an empty number such as `SC` fails as ShellCheck's lazy `read` does, only when a comment reaches it) |
| `--extended-analysis=bool` | supported |
| `-f`, `--format` | supported: `tty` (default), `gcc`, `checkstyle`, `diff`, `json`, `json1`, `quiet` |
| `--list-optional` | supported (same text) |
| `--norc`, `--rcfile=RCFILE` | supported |
| `-o`, `--enable` | supported (`all` or names) |
| `-P`, `--source-path` | supported (`SCRIPTDIR`, `:`-separated) |
| `-s`, `--shell` | supported |
| `-S`, `--severity` | supported |
| `-V`, `--version` | supported (prints 0.11.0's text) |
| `-W`, `--wiki-link-count` | supported (numbers wrap at 64 bits as GHC's `fromIntegral` does) |
| `-x`, `--external-sources` | supported |
| `--help` | supported |
| `-` (stdin) | supported |
| `--jobs N` | vsc only: check files on N threads (0: one per CPU); same output. Only exactly `--jobs N` or `--jobs=N` with a number counts: anything else (`--jobs x`, `--jo 2`, `-- --jobs`, `-f --jobs`) gets ShellCheck's own error, so a user who doesn't use it sees no difference |

Exit codes as ShellCheck: 0 no comments, 1 comments (and `-f quiet` stops at the first file with
any), 2 a file couldn't be read, 3 bad usage, 4 bad option values, and 1 with the program's name
and the message when ShellCheck itself would stop with an exception (below).

**Output.** All seven formats, including their quirks: tty and json print columns with tabs counted
to the next multiple of 8 while gcc, checkstyle and json1 count characters; json and json1 list
newer files first and repeat a file's comments once per file they mention; the tty format's code
excerpts, `^--` markers, "Did you mean:" with the fixes applied, the "For more information"
footer (`-W`) and colors; the `diff` format's unified diffs of all fixes, with three lines of
context, `\ No newline at end of file` and "none were auto-fixable".

**Fixes.** Every fix ShellCheck suggests (SC2006, SC2086, SC2164, SC2268, SC2295, SC2250,
SC2292, ... 26 codes), with the same replacements, precedences and insertion points, applied the
same way (Fixer.hs: overlapping fixes dropped, multi-line replacements, precedence order).

**Configuration.** `.shellcheckrc` (or `shellcheckrc`) in the file's directory and every parent,
then `$HOME/.shellcheckrc` (the password entry's home when `HOME` is unset) and
`$XDG_CONFIG_HOME/shellcheckrc` (when absolute; else `$HOME/.config/shellcheckrc`), built as the
directory package builds them; `--rcfile` replaces the search, `--norc` turns it off. Its keys and
the `# shellcheck` directives: `disable` (codes, ranges, `all`), `enable`, `source`, `source-path`
(with `SCRIPTDIR`), `shell`, `external-sources` (rc file only, SC1144 in scripts),
`extended-analysis`, and the messages for unknown keys and values (SC1107, SC1103, SC1145, SC1146,
SC1125). An rc file that doesn't parse gives SC1134; parse problems inside it (a carriage return:
SC1017) are reported at their place in the rc file, as ShellCheck does. Like ShellCheck, vsc looks
for the rc file of a file only after reading the file, and again only when the directory changes,
so a warning about an unreadable rc file (or `Warning: unable to read --rcfile`) is printed as
often and in the same place among the other messages.

**Sourced files.** `source`/`.` are followed as ShellCheck follows them: when the file was also
given as input, with `-x`, or with `external-sources=true`, looked up relative to the current
directory, then `-P` paths, then `source-path` directives (`SCRIPTDIR` joined as `joinPath`
does); their variables and functions count, their own comments are dropped unless `-a`, and
SC1090/SC1091/SC1093/SC1094 come out the same. "Given as input" compares canonical paths as the
directory package's `canonicalizePath` makes them (realpath of the longest existing prefix,
dangling links in the rest followed, `.` dropped and `..` kept).

**The system, as ShellCheck's binary sees it** (`sys_glue.c`):
- *Reading files*: `openBinaryFile` and the whole contents. Errors are printed as GHC shows them,
  with musl's `strerror` texts and GHC's error types (`x: openBinaryFile: invalid argument (Symbolic
  link loop)`, `does not exist (Not a directory)`, `inappropriate type (is a directory)`, `permission
  denied (Permission denied)`, `hGetContents: ...` for read errors, `<stdin>: hGetContents: ...`).
  Files that can't be reopened (stdin, pipes, FIFOs, `/dev/stdin`, character devices) are read once
  and cached by name, as ShellCheck's `siReadFile` does (a FIFO given twice, or `/dev/stdin` both
  given and sourced, read the same text).
- *Text*: bytes are read as ShellCheck's `decodeString` reads them (UTF-8 where it decodes,
  overlong forms and surrogates included, otherwise one Latin-1 character per byte), and every
  character test is GHC's `Data.Char` (Unicode 15.1): `$é` is a variable, U+00A0 splits shebang
  words, `toLower` and `toUpper` use the simple case mappings.
- *Writing*: as GHC's handles. The binary is linked with musl, whose locale codeset is ASCII when
  `LC_ALL`, `LC_CTYPE` or `LANG` (the first that is set and not empty) is `C` or `POSIX`, and UTF-8
  for every other value (including `en_US.ISO-8859-1`). A character the codeset can't hold (any
  non-ASCII one under ASCII; a surrogate, from a file name that isn't UTF-8 or from `\xED\xA0\x80`
  in a script, under UTF-8) makes that write fail after the characters before it, and the failure
  goes where ShellCheck sends it: the file's output stops and `file: <stdout>: commitBuffer:
  invalid argument (cannot encode character '\8217')` is reported, or, when the error report
  itself can't be written, the program stops with `shellcheck: <stderr>: hPutChar: ...` and exit 1.
  The json formats write UTF-8 bytes whatever the locale. stdout is written in 8192-byte blocks
  (line by line on a terminal) and stderr unbuffered, so `2>&1` interleaves the same way; write
  errors (`>/dev/full`, a closed pipe) are reported per file as ShellCheck does, and a broken
  pipe ends the run quietly with 0 as GHC's top handler does.
- *Names*: arguments, `SHELLCHECK_OPTS`, `HOME`, the current directory and realpath results are
  decoded as GHC decodes them (bytes that don't decode become U+DC80..U+DCFF) and encoded back on
  the way to the system; a sourced name that can't be encoded fails the file with `recoverEncode:
  invalid argument (cannot encode character '\233')`.
- *Internal errors*: ShellCheck's data flow analysis stops with an error after 1,000,000 nodes in
  one pass (`ShellCheck internal error, please report: DFA did not reach fix point` and the call
  stack line of the release build); vsc counts nodes the same way and prints the same error at the
  same point. Checked at the boundary: 340 nested loops need 994,319 nodes and both tools print
  the same 340 comments (ShellCheck in 196 s and 1.3 GB, vsc in 9 s and 146 MB); 341 need more
  than a million and both stop with the same message (`SC_SLOW=1 test/cases.py`). vsc has no other
  budget: every file ShellCheck finishes, vsc finishes 20 or more times faster.

## How it's tested: parity with ShellCheck

The parser is a faithful emulation of ShellCheck's Parsec parser, including how Parsec picks the
error message when several alternatives fail (the message and position of SC1072, and the
SC1073/SC1009 context lines, depend on it), so a broken script gets the same parse errors.

**Corpus.** Every shell script (by extension or shebang, zsh excluded) from 45 repositories, in
three corpora. Corpus 1 (1710 files, 6.5 MB): nvm, ohmyzsh, docker-install, kubernetes, shellcheck,
pure-bash-bible, rbenv, pyenv, asdf, acme.sh, n, bats-core, docker official-images. Corpus 2 (3645

field of every comment in `-f json1`, with `--fmt` stdout, stderr and exit status in all seven

shell features (`gen`), byte-level mutations of corpus files (`mut`), splices of corpus fragments
(`splice`), token insertions (`tok`), and since round 6 random bytes (`bytes`: invalid UTF-8, NUL,
CR, overlong forms, surrogates, BOMs, escape sequences), deep nesting and unbalanced quotes and
here-documents (`deep`), and generated scripts with characters of every Unicode category in names,
operators and words (`uni`).

## Known differences and limits

None in what ShellCheck prints for a file it finishes. What is left:

- **Where ShellCheck can't finish, vsc does.** ShellCheck runs out of memory on 9 corpus files
  (`acme.sh`, `nvm.sh` and 7 configure scripts, above) and prints `shellcheck: out of memory`;
  vsc checks them. Its data flow analysis stops with ShellCheck's own error at ShellCheck's own
  limit, so where ShellCheck would stop with that error after minutes, vsc stops the same way.
  vsc's memory on the largest of them is high (3.7 GB for a 1.6 MB configure script, where
  ShellCheck needs more than 6.5 GB): like ShellCheck it keeps a state per node, but its states
  are copied arrays where ShellCheck's are shared maps.
- **ShellCheck hangs when stdin is closed and `-` is read, or when stdout is closed**
  (`shellcheck - <&-`, `shellcheck x.sh >&-`): GHC's runtime creates its tick timer (a timerfd) at
  start, which takes the lowest free descriptor; with stdin closed that is 0 and reading `-` reads
  timer ticks forever, with stdout closed it is 1 and the first write waits forever for the timer
  to become writable (seen with strace). vsc reports `-: <stdin>: hGetContents: invalid argument (Bad file descriptor)` (exit 2),
  or treats the closed stdout as a failed write. Copying a hang would be worse for users.
- **Timing.** What is read from a FIFO or pipe that is still being written, and which file's
  output first meets a pipe whose reader has gone, depend on timing in both tools; vsc follows the
  same rules (open without blocking, read to the end; fail the write that meets `EPIPE`, then each
  later write; end quietly with 0), and agrees whenever the timing is the same.
- **The official binary, not every build.** vsc matches ShellCheck 0.11.0's release binary
  (static, musl). A ShellCheck built against glibc (as some distributions do) prints glibc's
  `strerror` texts, and encodes in Latin-1 under a Latin-1 locale instead of UTF-8; vsc doesn't
  follow those builds.
- **Not tested**: case-insensitive or network file systems, macOS and Windows (vsc reads paths
  with POSIX calls).
- `--jobs N` is an addition (above).
