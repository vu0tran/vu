Vu 0.2.0 compiler: translates .vu source to C, then builds a native binary with the C compiler.

Usage:
  vu check FILE.vu [--time] [--json] [--checks] [--caps]
      report errors only: no binary and no C compiler, so it takes milliseconds.
      --checks: for each loop, the index and arithmetic checks it still makes on every pass
      --caps: what the program can reach outside itself (files, programs, network, C code)
  vu run [--release] [--json] FILE.vu [ARGS...]
      quick unoptimized build (-O0), then run it with ARGS; --release builds optimized first.
      A panic prints the chain of calls that led to it (in quick builds).
      The binary is kept (in ~/.cache/vu/run), so the same program runs again without building;
      VU_RUN_CACHE=off builds every time. A script can start with: #!/usr/bin/env -S vu run
      Quick builds use clang when it's there (and CC isn't set); a big program's quick build is
      compiled in parts, in parallel, and each part is kept, so a rebuild compiles only what changed
      (VU_SPLIT=off: one C file; VU_SPLIT=always: split any program).
  vu build FILE.vu [-o OUT] [--debug] [--malloc] [--san] [--san-pool] [--tsan] [--emit-c FILE] [--time] [--static] [--wasm] [--profile] [--lib]
      optimized binary (-O3); --debug builds quickly instead. With VU_CACHE=DIR set, each binary is
      kept in DIR under a hash of its C, the C compiler's command, version and CPU, and the same
      build again is a copy (not for programs with extern C files). --static links every library in
      (the binary runs anywhere with the same CPU and kernel; with glibc, host name lookups need glibc there).
      --wasm: a WebAssembly (WASI) module, with zig's C compiler (no tasks, sockets or processes)
      --profile (build or run): optimized, and at exit the program reports where its CPU time went
      (by function and line, on stderr; all of it in vu-profile.txt, stacks in vu-profile.folded)
      --lib: a shared library (libFILE.so, .dylib on macOS) of the functions marked 'export fn',
      and a C header (FILE.h) declaring them, for C, or Python through ctypes
  vu get [FILE.vu]
      fetch the packages in vu.pkg (and the ones they need) and write vu.lock
  vu search [WORDS...] / vu add NAME [VERSION]
      the registry (VU_REGISTRY, else https://vulang.org/registry/index.txt): list packages, or add
      one to vu.pkg with the capabilities it takes, then fetch it (checked against the registry)
  vu publish NAME VERSION [DIR] [fs net os ffi]
      print the registry's lines for a git tag of a package (they go in by pull request)
  vu version
      prints the release (vu 0.2.0)
  vu new web NAME
      a folder NAME with a web app to start from: main.vu, public/, a Dockerfile, fly.toml,
      railway.json, README.md
  vu new app NAME
      a folder NAME with a web app with accounts on PostgreSQL, rendered on the server: sign-up,
      sign-in, a page for each user; main.vu, migrations/, public/, a Dockerfile, railway.json
  vu new api NAME
      a folder NAME with a JSON API on PostgreSQL, with accounts and sessions: main.vu,
      migrations/, a Dockerfile, railway.json, README.md
  --json: compile errors and panics are printed to stderr as one JSON object per line
