# Working on vgolint (golint/)

A map for changing vgolint without re-reading it. `README.md` says what it does and how well;
this file says where things are. Keep it current when you move things.

## Build and check

- `../vu check main.vu`: milliseconds, after every edit.
- `../vu build --release main.vu -o OUT`: build to a scratch path while comparing old and new.

## Files, in the order a run uses them

| file | what |
|---|---|
| `main.vu` | the CLI, `run`/`linters`/`config`/`cache` commands, workers, the per-package result cache (`spec_keys`: a package's key covers its sources and the lib hashes of its in-module imports; entries `p<key>` in the `vgolint3` format with a counts line) |
| `cfg.vu`, `doc.vu`, `rx.vu` | golangci-lint's config file (YAML/TOML/JSON into one tree), Go regexps |
| `load.vu`, `pkg.vu` | finding packages as `go list ./...` does; a package's files and issues |
| `scan.vu`, `parse.vu`, `ast.vu`, `resolve.vu` | the Go scanner, parser, flat tree, go/parser's object resolution |
| `tc.vu` | the type checker: `expr(&g, fs, pi, fi, n, hint)` gives an expression's type, `obj_type`, `under`, `core`, `type_str`, `load_pkg`; imported packages' cache on disk (`read_dep`, `ensure_file`, `# ---- the imported packages' cache`) |
| `vet.vu`, `printf.vu` | govet's analyzers; `vet.Walk` (all nodes and parents of a package, shared with staticcheck) |
| `sc.vu` | staticcheck's AST checks; `run` (`# ---- the driver`) calls each check; sections `# ---- CODE: what`. SA1000's pattern comes from `ir_const` (a constant, or a local the IR lifts to one) |
| `sc_g1.vu` .. `sc_g5.vu` | staticcheck v0.8.1's checks that came later: SA1xxx (g1, with text/template, time and url parsing), SA2xxx-SA4015 (g2), SA4018-SA4032 (g3, nilness over the IR model, `nil_std` table), SA5/6/9xxx (g4, its own IR model: dominators, reaching definitions, partial lifting), S1/ST/QF (g5); each `run` is called after sc.run with the package's nodes, `codes()` lists its checks |
| `vet_g6.vu` | govet's asmdecl, buildtag, cgocall, directive, framepointer, hostport, ifaceassert, lostcancel, slog, stdversion (`std_new_syms`), unsafeptr, waitgroup |
| `resyntax.vu` | Go's regexp/syntax parse checks and messages (SA1000), Unicode class names generated from Go 1.27.3's unicode tables |
| `ssa.vu`, `ssadata.vu` | the IR-modelled checks (SA4006, SA4009, SA4017; SA5011 is off, as in v0.8.1): lifted locals, liveness, phis, jump threading; std NoReturn/purity facts (generated by `tools/gen_ssadata.py` from `tools/dumpfacts`) |
| `unused.vu` | unused (the reachability graph) |
| `errcheck.vu`, `ineff.vu`, `lints.vu` | errcheck, ineffassign, the opt-in linters (lll and the depguard call among them) |
| `depguard.vu` | depguard's rule lists, gobwas/glob matching, allow/deny prefixes |
| `revive.vu`, `revive_core.vu` | revive's driver: which rules run (`conf_of`), `//revive:disable` directives (`intervals`), the confidence cutoff, issues with a line range (`pkg.Issue.endp` -> `proc.Iss.lto`: printed source lines, JSON `LineRange`) |
| `revive_a.vu`, `revive_b.vu`, `revive_c.vu` | revive's 23 default rules, one function each: naming and comments (a), control flow (b), errors and types (c); `names()` lists each file's rules |
| `deprecated.vu`, `deprdata.vu` | SA1019's deprecation notices |
| `proc.vu` | exclusions, nolint, sorting, max-issues: what golangci-lint does with issues |
| `printers.vu`, `htmltpl.vu` | output formats, byte for byte |
| `gofmt.vu` | the gofmt formatter as golangci-lint runs it: `format` (parse, rewrite rules, SortImports, simplify, print), the unified diff (`diff`, `tgs`) and golangci-lint's patch-to-issue changes (`changes_of`), `file_issues` (issues with their SuggestedFixes JSON); called from main.vu's `gofmt_issues` |
| `goimports.vu` | the goimports formatter (x/tools v0.50.0's imports.Process): fix.go's effect on code that compiles (`set_import_names`: unnamed imports whose package name isn't the assumed one get it), `merge_imports`, x/tools' own `sort_imports`/`sort_specs` (groups by `import_group` and LocalPrefix, comments moved after their spec, lines merged), `add_import_spaces`, then gofmt without -s; `pdq_sort` is Go's sort.Sort (not stable: equal specs and comments land where Go puts them); called from main.vu's `goimports_issues`, which takes the package names from the type checker |
| `fparse.vu` | go/parser for the printer: its own flat tree (`FT`) with every go/ast position (token.Pos: offset + 1), comment groups and lead/line comments as go/parser forms them; `npos`/`nend` are go/ast's Pos/End. Separate from parse.vu, which the linters use |
| `printer.vu` | go/printer (printer.go and nodes.go, function for function), `nodeSize`'s RawFormat printer (it stops once the node can't fit), gobuild.go, text/tabwriter and the trimmer |
| `doccmt.vu` | formatDocComment with go/doc/comment's parser and Printer.Comment (only what changes the text: curly quotes, list and code indentation, headings, link definitions moved to the end) |

To find a check: `grep -n 'SA4006\|"S1002"' *.vu`.

## Comparing with golangci-lint 2.14.0 on the monorepo

The session's scratch `gocmp/` has the scripts: `cmp.sh TAG CONFIG PATTERN` (counts per linter, the
issues only one tool reports), `rvcmp.sh VGOLINT RULE...` (revive rules against saved output),
`fullcmp.sh DIR CONFIG` (text and JSON, as sorted issue blocks). Give golangci-lint an empty cache
for each run (`GOLANGCI_LINT_CACHE=$(mktemp -d)`): its cache doesn't notice a change of revive's
settings.

## gofmt

- `vgolint fmt-debug [-s] [-r 'pat -> rep'] [-d] FILE` prints a file as gofmt formats it (`-d`: the
  diff and the changes golangci-lint makes issues of). `fmttest.vu` is the printer on its own:
  `fmttest cmp [-s] [-r RULE] LIST` (lines `SRC<tab>EXPECTED`) prints the files that differ,
  `bench`/`pbench LIST` time the parser, printer, tabwriter and trimmer.
- The comparison with gofmt: `tools/gofmt_gen.py NAME FLAGS FILES` runs gofmt (`$GOFMT`) on each
  file (expected outputs and a LIST for `fmttest cmp`), `tools/gofmt_mangle.py SEED OUT FILES` writes
  copies with spacing, line breaks, indentation, blank lines and comment alignment changed,
  `tools/gofmt_mangle2.py` also puts comments between tokens and generated doc comments above
  declarations. `tools/gofmt_cmp.sh DIR` compares both tools' issues (text and JSON) on a module,
  running golangci-lint with GOOS=linux GOARCH=amd64 (vgolint then takes the same build context
  from `go list`);
  `tools/fmtcases/` is a module of 40 hand-made cases for it.
- The printer keeps go/printer's quirks: nodeSize's cache keeps the first answer whatever the
  later maxSize, the comment map of a rewrite drops comments attached to replaced nodes, a doc
  comment directly above a declaration at column 1 is reformatted.

## goimports

- `vgolint imp-debug [-l PREFIXES] [-d] FILE` prints a file as goimports formats it (without the
  package names of fix.go's third pass, which come from the type checker in `run`).
- fix.go on code that compiles: every import is used and no reference is missing once the real
  package names are loaded, so nothing is added or removed; only the third pass's SetImportName
  can apply (an unnamed import whose package name differs from ImportPathToAssumedName's guess).
  Not ported: removing unused imports, adding missing ones (stdlib and module candidates), cgo's
  "C" decls are kept apart as mergeImports does but not tested (vgolint skips cgo packages).
- The comparison: `tools/imp_mangle.py SEED FRACTION FILES` rewrites import blocks in place
  (shuffled, regrouped, split into several declarations, comments, duplicate blank imports,
  aliases, empty blocks); `tools/imp_unalias.py NAMES FILES` drops aliases that equal a package
  name goimports doesn't assume (NAMES: `go list -deps -f '{{.ImportPath}} {{.Name}}'` lines), so
  the third pass puts them back; `tools/impcases/` is a module of 33 hand-made cases (cgo, local
  prefixes, renames, comments); compare with `tools/gofmt_cmp.sh` (pointing it at the binary).
- The release tags (go1.1 up to the toolchain's) come from `go list`'s build context with the
  other build tags (main.vu, `@gover=` in `c.build_tags`; load.vu `tag_true`).

## Helpers in sc.vu

`k(g, pi, n)` (kind), `nm(g, pi, n)` (name), `unparen`, `fmt_expr` (as go/printer prints it),
`obj_of(g, pi, n)` (the object an identifier refers to), `callee_name(&g, fs, &c, call)`
(`"strings.TrimSpace"`, `"(*bytes.Buffer).Write"`), `is_blank`, `may_side_effect`, `refers_to`,
`report(g, &c, n, code, msg)`. `vet.callee(g, pi, call)` gives the called function's object.
Several names repeat across modules (`report` in sc.vu, lints.vu and pkg.vu): check the module
you're in; `../vu check --dups main.vu` lists every such name.

## Adding a staticcheck check

1. Read the check in honnef.co/go/tools v0.6.1 (and its testdata) first.
2. Add `fn sXXXX(...)` in its own `# ----` section of sc.vu (ssa.vu when it needs the IR's
   liveness or values), and call it from `run`.
3. Make a case file under the synthetic corpus (the session's scratch `gocorpus/synth/`) with
   both what fires and what mustn't, and compare with golangci-lint (`tools/scen.sh DIR run`).
4. Run the corpus comparisons below; then the speed check.

## Parity and speed tools (tools/)

These read the session's scratch folder (`tools/env.sh` sets `$S` and Go's environment).

| tool | what |
|---|---|
| `gd.py [-r key] [REPO...]` | the 21-repo corpus: vgolint vs saved golangci-lint findings, per check |

| `scen.sh DIR ARGS...` | one command line, both tools: stdout, stderr, exit code |
| `bench2.sh DIR...`, `bench_edit.sh` | wall time, cold and cached; after editing one file |
