# Working on vgolint (golint/)

A map for changing vgolint without re-reading it. `README.md` says what it does and how well;
this file says where things are. Keep it current when you move things.

## Build and check

- `../vu check main.vu`: milliseconds, after every edit.
- `../vu build --release main.vu -o OUT`: build to a scratch path while comparing old and new.

## Files, in the order a run uses them

| file | what |
|---|---|
| `main.vu` | the CLI, `run`/`linters`/`config`/`cache` commands, workers, the per-package result cache (`spec_keys`: a package's key covers its sources and the lib hashes of its in-module imports; entries `p<key>` in the `vgolint3` format with a counts line) |
| `cfg.vu`, `doc.vu`, `rx.vu` | golangci-lint's config file (YAML/TOML/JSON into one tree), Go regexps |
| `load.vu`, `pkg.vu` | finding packages as `go list ./...` does; a package's files and issues |
| `scan.vu`, `parse.vu`, `ast.vu`, `resolve.vu` | the Go scanner, parser, flat tree, go/parser's object resolution |
| `tc.vu` | the type checker: `expr(&g, fs, pi, fi, n, hint)` gives an expression's type, `obj_type`, `under`, `core`, `type_str`, `load_pkg` |
| `vet.vu`, `printf.vu` | govet's analyzers; `vet.Walk` (all nodes and parents of a package, shared with staticcheck) |
| `sc.vu` | staticcheck's AST checks; `run` (`# ---- the driver`) calls each check; sections `# ---- CODE: what` |
| `ssa.vu`, `ssadata.vu` | the IR-modelled checks (SA4006, SA4009, SA4017, SA5011): lifted locals, liveness, phis and sigmas; std NoReturn/purity facts (generated by `tools/gen_ssadata.py` from `tools/dumpfacts`) |
| `unused.vu` | unused (the reachability graph) |
| `errcheck.vu`, `ineff.vu`, `lints.vu` | errcheck, ineffassign, the opt-in linters |
| `deprecated.vu`, `deprdata.vu` | SA1019's deprecation notices |
| `proc.vu` | exclusions, nolint, sorting, max-issues: what golangci-lint does with issues |
| `printers.vu`, `htmltpl.vu` | output formats, byte for byte |

To find a check: `grep -n 'SA4006\|"S1002"' *.vu`.

## Helpers in sc.vu

`k(g, pi, n)` (kind), `nm(g, pi, n)` (name), `unparen`, `fmt_expr` (as go/printer prints it),
`obj_of(g, pi, n)` (the object an identifier refers to), `callee_name(&g, fs, &c, call)`
(`"strings.TrimSpace"`, `"(*bytes.Buffer).Write"`), `is_blank`, `may_side_effect`, `refers_to`,
`report(g, &c, n, code, msg)`. `vet.callee(g, pi, call)` gives the called function's object.
Several names repeat across modules (`report` in sc.vu, lints.vu and pkg.vu): check the module
you're in; `../vu check --dups main.vu` lists every such name.

## Adding a staticcheck check

1. Read the check in honnef.co/go/tools v0.6.1 (and its testdata) first.
2. Add `fn sXXXX(...)` in its own `# ----` section of sc.vu (ssa.vu when it needs the IR's
   liveness or values), and call it from `run`.
3. Make a case file under the synthetic corpus (the session's scratch `gocorpus/synth/`) with
   both what fires and what mustn't, and compare with golangci-lint (`tools/scen.sh DIR run`).
4. Run the corpus comparisons below; then the speed check.

## Parity and speed tools (tools/)

These read the session's scratch folder (`tools/env.sh` sets `$S` and Go's environment).

| tool | what |
|---|---|
| `gd.py [-r key] [REPO...]` | the 21-repo corpus: vgolint vs saved golangci-lint findings, per check |
| `cmp_cfg.py`, `own_cmp.py` | any config; each repo's own config, printed blocks in order |
| `scen.sh DIR ARGS...` | one command line, both tools: stdout, stderr, exit code |
| `bench2.sh DIR...`, `bench_edit.sh` | wall time, cold and cached; after editing one file |
| `gen_lintersdb.py`, `gen_misspell.py`, `gen_ssadata.py` | generated tables |

The x/ modules comparison (`gox/cmp.py`) is in the scratch folder too.
