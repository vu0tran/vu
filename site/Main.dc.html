Fewer tokens. Less for the model to screw up.

No braces. No semicolons. No lifetime annotations. No header files. Types are inferred inside functions and written out only where a human needs them: the signature. Every token the model doesn't write is one it can't get wrong, and one you don't pay for.

Models write the code now. Models will attack it too.

Nobody is reviewing all the code models write, and models are getting scary good at finding the holes in it. So Vu doesn't count on review. Memory bugs and data races don't compile. A function can only touch the files, network and processes you hand it, and a dependency only what you grant it. Then we attacked every feature, round after round, until a whole round came back empty.

What is claimed is:

  1. 1.
    Memory bugs don't compile
    Every value has one owner. Borrows can't escape or outlive what they borrow, and nothing changes while it's borrowed. There's no unsafe to reach for. Indexes are bounds-checked, and integer overflow stops the program instead of quietly wrapping around.
  2. 2.
    Data races don't compile either
    In a par loop, each iteration owns its own element and everything else is read-only. Tasks share only channels and read-only Shared values.
  3. 3.
    Code only gets what it's handed
    Files, processes, the network and C are capabilities. Only main gets them, nobody can forge them, and a dependency that isn't handed Net can't open a socket. Period.
  4. 4.
    We attack it before you have to
    637 programs, each written to break one rule, run on every change under AddressSanitizer, UBSan and LeakSanitizer, and threaded code under ThreadSanitizer.

The fine print: Vu is v0 and hasn't had an outside security audit. Its runtime (memory, scheduler, TLS glue) is C, and the same sanitizer runs cover it.

Error messages that tell you what to type.

An agent fixes code in a loop: write, compile, read the error, try again. Vu's errors are written for that loop. Each one names the line, says what's wrong in plain English, and usually spells out the fix. No forty-line template backtraces. Watch: a mistake, the message, the fix.

Fast as Rust, with every safety check still on.

Vu compiles to C and lets gcc do the optimizing. It never switches off a safety check to win a benchmark: every index is bounds-checked and every integer operation overflow-checked. In hot loops it checks once before the loop instead of on every step, so gcc still vectorizes. And because the compiler knows exactly when every value dies, it recycles memory with no runtime checks. That's how it beats C by 2.6× on binary-trees. Seconds, lower is better.

Hand your model the spec. See what it writes.

The whole language fits in one short document, written to be pasted into a prompt. You need Linux and gcc. That's it: the first run builds the compiler from the C it wrote of itself.

~/vu
# get it
$ git clone https://github.com/vu0tran/vu && cd vu
 
# run a program (builds the compiler the first time)
$ ./vu run examples/binarytrees.vu 16
 
# every compile error, in milliseconds
$ ./vu check examples/json.vu
 
# an optimized native binary
$ ./vu build examples/nbody.vu -o nbody
